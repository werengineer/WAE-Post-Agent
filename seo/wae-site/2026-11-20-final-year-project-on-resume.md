## Body

# How to Write Your Final Year Project on Your Resume

For most freshers, the final year project is the strongest thing on the resume. You have no job history, so this is the one place where you show what you can actually build. Many students waste it with one vague line such as "Made a project on IoT". This guide shows you how to do it better.

## The short answer

Give your final year project its own entry under a "Projects" heading, placed right after "Education" if you have no work experience. Write the project title and the tools you used, then add 2 to 4 short bullets. Each bullet should say what you did, with which tool, and what the result was. Add a GitHub or demo link if the work is public.

## Where to place the project on your resume

- **No work experience yet:** put "Projects" directly after "Education". Recruiters read the top of the page first.
- **You have an internship:** put "Experience" first and "Projects" next.
- **You have more than one project:** keep a "Projects" section and list the most relevant one first. Your final year project usually goes first because it is the biggest.
- **Length:** a fresher resume is usually kept to one page. Check if your college placement cell has its own format and follow it where it differs.

## What to include in the entry

1. **Project title.** Use a plain name that says what it is, for example "Attendance system using face recognition".
2. **Type and time.** Write "Final Year Project" and the year or months.
3. **Tools and technologies.** List the languages, frameworks, boards, software or standards you used.
4. **Your role.** In a team project, say what you built yourself. Do not claim the whole team's work.
5. **2 to 4 bullets** on what you did and the result.
6. **A link.** GitHub repository, demo video, or a verified project profile.

## A simple bullet formula

Use this pattern: **Action + what you built + tool + result.**

- Weak: "Worked on a web application."
- Better: "Built the login and booking modules of a web app using React and Node.js; tested with 10 sample users." *(example only; use your own numbers)*

Rules that help:

- Start with a strong verb: built, designed, tested, programmed, analysed, simulated, reduced.
- Add a number only if it is true and you can explain it. If you do not have one, describe the result in words: "the system sent an alert when the sensor crossed the set limit".
- Keep each bullet to one or two lines.
- Never add a number you cannot defend in an interview. The viva and the interview will test it. See our guide on [how to prepare for your project viva](/blog/final-year-project-viva-preparation).

## Three example entries

These are examples of format only. Replace every detail with your own work.

**CSE**
> **Attendance System Using Face Recognition** | Final Year Project | 2026
> Tools: Python, OpenCV, SQLite
> - Built the face detection and matching module and stored attendance records in a database.
> - Tested the system on a set of sample images and fixed cases where lighting caused wrong matches.
> - Wrote the project report and the setup guide. GitHub: *(your link)*

**ECE**
> **Soil Moisture Monitor With Alerts** | Final Year Project | 2026
> Tools: ESP32, soil moisture sensor, Arduino IDE
> - Designed the circuit and wrote the firmware to read the sensor and send a reading over Wi-Fi.
> - Calibrated the sensor against dry and wet soil samples.
> - Built a simple dashboard to show readings. Demo video: *(your link)*

**Mechanical**
> **Low-Cost Hand-Operated Seed Sower** | Final Year Project | 2026
> Tools: SolidWorks, basic fabrication
> - Modelled the sower in SolidWorks and prepared the drawings for fabrication.
> - Built a working prototype with a team of four; my part was the seed-metering mechanism.
> - Tested seed spacing over several trials and adjusted the design.

## How to add a GitHub link the right way

- Link to the repository of the project, not only to your profile.
- Add a README with: what the project does, how to run it, the tools used, and a screenshot. A recruiter may only read this page.
- Make sure the code is yours. Know every file you wrote and be able to explain it.
- Remove passwords, API keys and personal data from the code before you make it public.
- Keep the repository public if you put the link on the resume. A private link shows an error.

## Match the project to the job

Do not send the same resume everywhere. Read the job post and look at the skills it asks for. If you applied for a data job, put the data parts of your project first. If you applied for an embedded role, put the firmware and hardware parts first. Use the same words as the job post only where they are true for your work.

## Mistakes to avoid

- **One line only.** "Final year project on machine learning" tells the recruiter nothing.
- **Listing tools you did not use.** Only list what you can discuss.
- **Claiming team work as your own.** Say "my part" clearly.
- **Made-up results.** If you cannot explain how a number was measured, remove it.
- **Buzzwords without proof.** "Innovative", "cutting-edge" and "AI-powered" do not help unless the bullet shows what was built.
- **Broken links.** Open every link in a private window before you send the resume.
- **Different story in the interview.** Keep the resume and your spoken answer the same.

## FAQ

### Where should I put my final year project on my resume?
Put it in a "Projects" section right after "Education" if you have no work experience. If you have an internship, put "Experience" first and "Projects" after it. List the most relevant project first.

### How many bullet points should a project have?
Two to four short bullets are enough. Each bullet should say what you did, which tool you used, and the result. One or two lines per bullet keeps the resume easy to scan.

### Should I include my final year project if it was a team project?
Yes. Say it was a team project and write clearly what you built yourself. Be ready to explain the whole project too, because interviewers often ask about the parts you did not build.

### Should I add numbers and percentages to project bullets?
Add a number only if it is true and you can explain how you measured it. If you have no measured result, describe the outcome in plain words instead. A false number can hurt you in an interview.

### Do I need a GitHub link for my project?
It is not required, but it helps. Link the project repository with a clear README, and remove any passwords or keys first. If the code cannot be public, add a demo video or screenshots instead.

### What if my final year project is not related to the job I want?
Keep it, but write the bullets to show skills that the job needs, such as testing, teamwork, data handling or circuit design. You can also add a smaller personal project that is closer to the role.
